# lhg-cp-matrix：对比矩阵与差异化建议

> 目标：把 N 份竞品画像压成一张表，再从表里"算"出差异化打法。
> 核心纪律：**建议必须从矩阵里长出来，不能从天上掉下来。**

## 1. 何时使用

- 2 个以上竞品的画像（lhg-cp-profile 产出）已齐，准备横向对比时
- 用户说"帮我看看我们跟对手差在哪"时
- 竞品分析流水线的 Phase 3，本 skill 是核心

## 2. 输入与输出

- **输入**：2-6 份竞品画像 + 分析框架卡（lhg-cp-frame 产出）+ 我方产品信息（如有）
- **输出**：对比矩阵表 + 差距分析 + 差异化建议报告（3-5 条）

## 3. 第一步：建对比矩阵

矩阵的行 = 框架卡里的可观测指标，列 = 竞品（+ 我方列，如有）。单元格只填**事实**，不填评价：

```markdown
| 维度/指标 | 竞品 A | 竞品 B | 竞品 C | 我方 |
|---|---|---|---|---|
| 免费版边界 | 100 条/月 | 不限条数但无 API | 无免费版 | 500 条/月 |
| 入门价（截至 2026-10） | ¥29/人/月 | ¥19/人/月 | ¥49/人/月 | 未定价 |
| 应用商店评分（截至 2026-10） | 4.6 | 4.2 | 4.8 | — |
| 差评集中点 | 同步慢 | 功能少 | 贵 | — |
```

填表规则：

1. **一格一事实**：单元格里不许出现"较好""不错"这种评价词，评价留到第 4 步。
2. **缺数据就空着**：写"未公开"，不许用猜测填格子。空太多说明情报工作没做到位，打回去补。
3. **单位统一**：价格统一到同一币种同一口径（如"¥/人/月"），评分统一到同一平台。
4. **标截至日期**：时间敏感行（价格、评分）在表头或脚注统一声明"截至 <日期>"。

## 4. 第二步：差距分析（读表）

横向读表，找四类信号，每类找 2-4 个：

- **共识区**（大家都有的）：这是赛道的"入场券"，我方没有就是短板。如：所有竞品都有"多端同步"，我方没有 → 这是必补项，不是差异化。
- **空白区**（都没做好的）：这是机会。如：所有竞品差评都集中在"客服响应慢" → 服务可能是突破口。
- **分化区**（做法分岔的）：这是定位分水岭。如：A 走高价高服务，B 走低价自助 → 我方必须选一边站，不许"都要"。
- **我方独占区**（只有我方有的）：这是现有优势，检查它是不是真优势（用户在乎吗？竞品抄的成本高吗？）。

## 5. 第三步：推导差异化建议（3-5 条）

每条建议的固定格式：

```markdown
### 建议 n：<一句话打法>
- **打什么**：针对矩阵中的哪个空白区/分化区/对手软肋（← 引用具体单元格，如"矩阵第 3 行：竞品 A/B 差评集中在同步慢"）
- **怎么打**：具体动作（做什么、做到什么程度、用什么验证）
- **代价**：要投入什么（研发/钱/时间），不说代价的建议 = 空话
- **风险**：对手最可能的反制是什么
```

建议的质检（写完逐条过）：

1. 追溯得到矩阵单元格吗？→ 追溯不到，删。
2. 有具体动作和验证方式吗？→ 只有"加强产品力"这种词，删。
3. 代价和风险写了吗？→ 没写，补。
4. 这条建议换个赛道也成立吗？→ 成立，说明太泛，删（比如"提升用户体验"放哪都成立）。

### 建议优先级排序

3-5 条建议写完后，按"影响 × 可行性"排个序，排第一的标"先干这个"：

- **高影响 + 高可行**：先干，写进下个迭代
- **高影响 + 低可行**：立项预研，别直接排期
- **低影响 + 高可行**：顺手做，别专门立项
- **低影响 + 低可行**：删掉，不占用报告篇幅

报告的"结论先行"区只放排序后的前 3 条——用户的时间只够看 3 条。

### 什么时候不做矩阵

三种情况别硬做对比矩阵，做了也是水货：

1. **竞品少于 2 个**——只有一个对手时用 lhg-cp-profile 深挖单点，不用矩阵。
2. **情报缺口超过 40%**——格子大面积"未公开"，先回去补情报（委派 scout），不要拿着半张表硬推建议。
3. **赛道还在萌芽期**——玩家都没定型，矩阵今天做完下个月就过时，改做"赛道观察清单"轻量跟踪。

## 6. 第四步：报告模板

```markdown
# <赛道>竞品分析报告（<日期>）
## 0. 结论先行（给没时间的人）
- 差异化建议 1：<一句话>
- 差异化建议 2：<一句话>
- 差异化建议 3：<一句话>
## 1. 对比矩阵
（第 3 步的表）
## 2. 差距分析
### 共识区 / 空白区 / 分化区 / 我方独占区
## 3. 差异化建议（3-5 条，见第 5 步格式）
## 4. SWOT（每个主要竞品四象限，见 swot 命令）
## 5. 信息缺口
- <哪些格子是"未公开"，以及补齐的计划>
## 6. 来源清单
- <每条关键结论的出处链接>
## 7. 声明
- 本报告基于公开信息整理，仅供参考，不构成投资/经营建议；价格评分类数据截至 <日期>。
```

## 7. 矩阵填表常见坑

- **坑 1：口径不统一**——A 的价格是"¥/人/月"，B 的是"$/年"，直接并排放。填表前先定换算口径，表头写清。
- **坑 2：拿不同时间的数据比**——A 的评分是去年的，B 的是上周的。时间敏感行统一"截至 <日期>"，过期重验。
- **坑 3：把"没写"当"没有"**——官网没写某功能，不等于没有。区分"未公开"（没找到）和"无"（确认没有），后者需要证据。
- **坑 4：矩阵越做越大**——指标超过 20 个，表就没法读了。指标超过 15 个时砍到核心 12 个以内，砍掉的进附录。
- **坑 5：我方列双标**——我方格子写"体验极佳"，竞品格子写"4.2 分"。我方列用同一套指标、同一口径，不许美化。

## 8. 反模式（不要这么做）

- ❌ 矩阵单元格里写评价词（"体验好""性价比高"）——评价是第 4 步的事，混在一起表就没法读
- ❌ 用猜测填"未公开"的格子——空着是诚实，填猜测是造假
- ❌ 建议追溯不到矩阵——这是本 skill 的头号红线
- ❌ 共识区当差异化讲（"我们也要做多端同步"也算建议？那是补课，不是差异化）
- ❌ 建议不写代价和风险——不说代价的建议谁都会提
- ❌ 结论先行区写 10 条——超过 5 条说明你没想清楚优先级

## 9. 自检与反馈

每次执行完本 skill，做一次轻量自检：

1. 矩阵里有"未公开"的格子吗？→ 有是正常的，但超过 30% 说明情报没做到位。
2. 每条建议都能指到具体单元格吗？→ 指不到的删掉。
3. 建议里有"放哪都成立"的泛话吗？→ 有就删或具体化。
4. 代价和风险每条都写了吗？→ 没写的补上。

如发现本 skill 自身的方法论缺陷，按以下流程反馈：

- **标准冒烟用例**：用 3 份 AI 笔记竞品画像走一遍本 skill，检查矩阵是否一格一事实、建议是否可追溯、有无泛话建议。
- **一键提 issue**：确认问题后，以 `[QC] <一句话问题>` 为标题、正文写清"复现输入 → 错误输出 → 期望输出"，提交到 https://github.com/lhg-plugs/lhg-competitor/issues。
